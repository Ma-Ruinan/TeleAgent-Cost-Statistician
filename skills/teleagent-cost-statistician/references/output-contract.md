# 输出口径

默认每个对象生成一个 Excel、一个 Word，以及本地回查用的执行数据 JSON。三份文件使用相同的测试ID关联。所有真实日志和结果保存在调用者指定的本地结果目录。

## 九项指标

| JSON字段 | 展示名称 | 计算与显示 |
| --- | --- | --- |
| seconds | 耗时 | 用户提交至最后完成回复的时间差，JSON保留秒；Excel按时长数值显示时分秒，逐次保留毫秒，均值显示至秒 |
| llm_calls | LLM完成调用数 | 已完成且有用量的模型调用去重计数，不含失败重试尝试 |
| input_tokens | 输入Token | 每次调用的输入累加，含缓存；Excel和Word除以10000，以万为单位 |
| output_tokens | 输出Token | 每次调用的输出累加，除以10000显示为万 |
| cache_rate | 缓存命中率 | 缓存读取Token除以累计输入Token，输入量为零时未取得 |
| tool_calls | 工具调用 | 按调用标识去重，包含失败调用 |
| tool_errors | 工具错误 | 明确错误状态、内部错误标记或非零退出码，按调用标识去重 |
| search_calls | 搜索调用 | 本对象专用搜索工具调用，包括报错调用；不把网页抓取、命令内联网等自动等同为专用搜索 |
| artifact_count | 交付文件数 | 成功交付工具登记且磁盘存在的唯一路径数；同路径重复登记计一个，不同格式路径分别计数 |

Token逐次显示四位小数，能够对应回整数Token；均值显示六位小数。JSON中的Token保留原始整数。累计输入会包含多轮反复读入的上下文，不按独特文本去重。

## 测试次数和均值

完整重新提交同一道题，建立新独立测试。原记录保留，不覆盖第一次。明确的继续指令属于原测试后续执行段，按段记录九项原值，再合并为一次测试。内部模型重试、工具重试不新增独立次数，但新的工具调用标识仍计入工具调用。

完整测试耗时包含段间等待。活动耗时为各段耗时之和，段间等待另列。没有最后完成时间的任务，九项中前八项保持缺失；JSON的 observed_partial 保留实际观察到的局部信息。交付文件数只反映登记且存在的文件，可以明确为零。

先对同题各次有效数值求均值，再对题目等权求对象主要均值；全部独立测试按次平均另列。每项分别列有效题目数和有效测试次数。取得完整数值的失败执行参与统计，缺失不补零。缓存比例的主均值为题目等权算术平均；输入量加权的整体缓存比例另列，只使用缓存量和输入量均可得的测试。

## Excel

任务均值、逐次记录、执行分段、口径与来源四张表。逐次记录保存九项指标、模型记录、附加条件、会话和用户消息标识、来源路径、交付路径及补充页面证据。汇总使用Excel公式并保存本次计算缓存；新增大量数据时重新采集生成，计算范围自动随记录数扩展。

## Word

记录本批范围、模型条件、对象均值及有效次数。按测试ID和题目分别列结果状态、追加继续情况、工具错误时间和摘要、模型重试证据、交付文件与来源。每个具体问题需有时间、调用标识及 JSONL 行号或数据库 part 标识。存在一条日志错误不等于整道题失败，文件存在也不直接等于内容合格。

Agent应阅读JSON后补充有依据的观察，必要时通过 report.py 的 --analysis 参数重新生成Word；补充JSON为按 run_id 组织的字符串数组字典。说明具体问题造成的已观察影响，推断注明依据。错误摘要只有弃用警告时，不直接认定警告是命令失败根因。正文用清晰中文，结合实例，避免双引号和破折号；回查JSON保留日志原文。

## 需要人工核实的关联和页面证据

题目默认仅在去除空白后作完整匹配。WorkBuddy另去除末尾场景标签，但把标签保留为条件。改写的题目不自动模糊匹配。可用 --mapping 提供JSON数组，每项包含 session、user_message、task_id，以及 role=new 或 continue；映射须来自人工核实。

页面证据通过 --observations 提供JSON数组。每项以 run_id、session、user_message 中一个或多个字段唯一定位测试，包含 page_status、page_response、evidence；实际确认拒答时可加 outcome=refused。证据来源必须明确，例如用户确认的页面回复。不能把页面显示已完成直接当作已交付，也不能把某题的一次观察套用到其他次。

版本、模型、失败重试等字段没有可靠记录时标为未记录，不推断数值或型号。九项指标不包含金额；没有单价与可靠计费记录时，不把日志中的零费用解释为实际免费。
